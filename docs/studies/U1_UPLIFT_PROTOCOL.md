# U1-UPLIFT: Runesmith against the same model with a simple fixed script, at equal budget

Stage-0 declaration, written 2026-10-05 before any U1 task, repository checkout, seed or model call exists.
Designer: Claude Opus 5.5 (integration operator), at the lead investigator's request ("run it today, sealed"; the
result is reported in the paper whatever it shows). This file is sealed by its SHA-256 in `SEAL.txt`, and the same
file is pushed to the project's GitHub remote before the first task is generated, so the push time is an outside
timestamp.

## Question

With the same free model and the same budget, does Runesmith's released repair organ repair more fresh regressions
than the same model driven by a simple fixed script without Runesmith's organ?

This is a comparison with the strongest fixed scaffold the record has defined, not a comparison with a one-shot prompt.
It is not the record's weak-model amplification experiment (card W) and not a substitution test.

## Arms (three, one round each)

- **R-C7 (primary "with Runesmith").** The released Core's repair organ at generation C7 (`gen-e12d76179a3d`, as
  shipped in the release's generation library), run by the released Core kernel.
- **R-g0 (secondary).** The same, at the shipped default generation g0.
- **DIRECT ("without Runesmith").** SR6-W's DIRECT arm, unchanged (`RUNESMITH-SR6W-WEAK-2026-09-24/baseline_organ/direct.py`):
  "the strongest fixed scaffold without model navigation": lexical retrieval of whole files by issue-to-path and
  symbol overlap up to the same 32 KB cap, the same test-feedback loop, all calls spent on edits. It was defined on
  2026-09-24 for SR6-W and is not modified for U1. It runs inside the same kernel envelope only so that budgets,
  confinement and judging are identical.

## Model, route, envelope

- Model: `gpt-oss-20b` (SR7's repair model), for every arm.
- Route: a free route (Groq's free tier) if it serves `gpt-oss-20b`; otherwise OpenRouter at a total spend below
  US$2. The route used is recorded per call. No other model is used; there is no author model (nothing is authored).
- Envelope, identical for every arm (SR7's): at most 5 model calls, 8,192 tokens, 45 signal runs, 64,000 request
  bytes and 1,800 seconds per session.

## Tasks

- Family: SR7's family, synthetic single-line regressions (comparison swaps, and/or exchanges, removal of `not`, sign
  changes, integer off-by-one, flipped boolean returns) injected into test-covered function bodies, one task per
  source file, generated by the program's existing pool generator with its existing validation (the mutant makes at
  least one targeted test fail; the pristine source passes).
- Repositories: public open-source Python projects never used by the program, so that anyone can regenerate the
  pool. Rule, fixed now: take, in this order, `pallets/click`, `mahmoud/boltons`, `Python-Markdown/markdown`,
  `pytoolz/toolz`, each at its latest release tag on 2026-10-05; use the first two whose own test suite passes at that
  tag with the experiment's interpreter (offline after checkout, no network during tests); record tag and commit.
- Size: 30 tasks, 15 per repository (fewer only if a repository yields fewer valid tasks; then the other fills to 30),
  selected by a seeded draw recorded in `SEEDS.json` before generation. Tasks are validated mechanically only; no
  person or model reads a task, its issue or its outcome before the analysis.
- Public information per task, identical for every arm: the failing test identifiers and a sanitized failure excerpt
  (SR7's issue template). The judge: the full targeted test files on a fresh pristine snapshot (SR7's strict success).

## Execution

One HMAC-ordered, interleaved queue of 90 sessions (30 tasks x 3 arms), the same task revision for every arm.
Transport failures are retried by the route layer; a session censored by transport after its retries is re-queued
once at the end, and if still censored it is reported as censored, never scored. No outcome is read until the end
marker of the evaluation.

## Analysis (declared now)

- Primary endpoint: strict success per session. Primary test: R-C7 > DIRECT, exact one-sided sign test on the tasks
  where exactly one of the two succeeded (discordant tasks), alpha = 0.025. The mirrored test (DIRECT > R-C7) is
  declared and reported as "the fixed script did better" if its p <= 0.025; otherwise the verdict is NULL.
- If fewer than 4 tasks are discordant, the verdict is "no difference detectable at this size", whatever the counts.
- Secondary, descriptive, both directions reported: R-g0 vs DIRECT; R-C7 vs R-g0 (the first C7-against-g0 data,
  n = 30, exploratory); per-repository counts; false promotions (public pass, strict fail); organ errors; seconds and
  calls per strict success; censoring by arm.
- Every number of every arm is reported in the paper and the evidence dataset, with this protocol's digest.

## What a pass would and would not license

A pass licenses: "on fresh synthetic single-line regressions in two public Python repositories, with one free model
(gpt-oss-20b) and an equal budget, Runesmith's released repair organ (C7) repaired more tasks than the same model
driven by the strongest fixed script the record defined." It does not license general uplift, natural-bug repair,
other models, other task kinds, or cost claims. A null or a reverse result is reported with the same prominence.
