# Changelog

## Unreleased: release hardening (2026-09-27)

**A newcomer with one free key gets a working, checked app (2026-10-05).** An acceptance run on a clean machine with one free Google AI Studio key built a working Reading Log app, but took an hour: 36 of 38 model calls failed, no check ever ran, and the page pointed to a card that was not there. Seven faults, in the order they cost the most.
- **The project's tests are found where the draft put them.** Checks always ran `tests/` as a package, so a draft whose test sat in the folder's top level (or in a `tests/` with no `__init__.py`) failed with "Start directory is not importable", and the owner's acceptance checks never started behind it. They now run the tests in `tests/` (a package or a plain folder) and, when there is no `tests/` or it holds no test, every `test*.py` in the top folder (a project that has tests runs exactly what it ran before); with no test at all the output says where tests belong. The author is told the layout too (a `tests/` folder with an empty `__init__.py`, or `test_*.py` files in the top folder).
- **A free key is paced, not drained.** Every retry spends from a small allowance, and one click used to send up to four requests (a build three). Now a "429" stops the retrying at once, is remembered in `.runesmith/PACING.json` until the service's own reset (its `Retry-After`, the "retry in 34s" in its message, or, for a daily limit, midnight on the US Pacific coast; a refusal that names no time is held two minutes, and one right after that is held until the day's end, or longer each time for a service that is not Google), and says so in plain words with the time; the next click, the next scheduled round and the Test button send nothing until then, and a new key lifts the hold. A short wait the service names (a few seconds) is waited out once. A "503" ("high demand") is asked once more after a longer wait. A free-tier instrument gets at most one retry, and when a second provider is set up the request goes to it at once. With one provider only, the Overview says when it is back and suggests adding a second free provider (naming the guide's chapter on free thinking power, and linking it once the guide has an address); the model row shows the hold. A call that ended this way nothing ran for, so it uses up none of the milestone's tries.
- **The Try card appears for what was built.** It looked only in a README and in the milestones' text, so an app described nowhere stayed without its card while the Overview said "Try what was built below". It now also reads the brief and the applied drafts' run instructions and file purposes (one sentence of a description is cut at its full stop), falls back to the program's own entry point (`python name.py --help`, or `python -m package`), and the Overview promises the card only when it is there.
- **A busy service gets the same plain line as a rate limit.** A 503 or 502 showed a cut-off block of JSON and "failed (transport)". It now says the model is busy or at its free limit and what to try, in the Live log too ("is at its free limit", "is busy" instead of "failed (transport)"); what the service said is kept under "What the service said" in Activity and on the model's row.
- **The model row tells the truth.** "Tested just now" stayed on the row after a failed test; it is shown only for a test that worked, with its age, and a test that could not run replaces it. "List models" without a key says "Add your key first" instead of "not running".
- **With one model the check autopilot says what it needs.** It cannot cross-check checks without a second model: the page now says so and offers "Approve them myself" in one click, next to "Add a second model".
- **Smaller:** the Overview's last-attempt line no longer runs two sentences together after a cut error ("Spikes i 3 tries in a row"), and no longer says "This folder is empty" once files were written (the map from the first start was the only source). The guide's first chapter now says that `RUNESMITH.md` appears in the folder and what it holds.
- Tests: `tests/test_build_steps.py` (the test layouts, acceptance behind them, the author's prompt), `tests/test_free_key_pacing.py` (429 and 503 with a stand-in service and with the real transport, the hold across clicks, the second provider, the free-tier cap, the Overview, the Test button, List models), `tests/test_try_it.py` (the sources of the Try card and the Overview's promise), `tests/test_newcomer_path.py`.

**A one more try cut short by a restart no longer blocks its milestone for good (2026-10-05).** In a long unattended run, the one more try (another model) was started for a milestone whose three tries had failed, the Studio was restarted while it worked, and from then on every build of that milestone ended at once with "Unresolved author allowance receipt ...; reconcile it before another call". The Overview's "Needs you" stayed empty, so the project stood still with nobody told. Any crash or power cut in the middle of a one more try did the same.
- **Cause.** The one more try's receipt is written "started" before its call and settled when the call ends. After a restart the model's saved job was fetched, as it is for an ordinary try, but nothing tied the fetched answer to the one more try's receipt (an ordinary try is found through its own record; the one more try had none), so nothing ever settled it, and a started receipt blocks its milestone's tries until it is settled. The schedule skipped a milestone whose records were unclear, so it never reached the owner either.
- **Fix.** The call's saved packet now names its receipt, and fetching the answer settles that receipt: answered (with its draft, which is then checked like any other), or refused with its answer kept, or failed with the reason. On a restart, and before every build, a one more try that was started and never finished is settled from what is saved, with no model call and nothing sent again: a call whose saved job can still be fetched is left for the fetch; one whose answer was kept is recorded as answered; any other used its one more try and is recorded as failed, "interrupted by a restart". A saved request of it that can no longer be fetched stops holding the milestone back. A restart says in the activity which milestone it settled and how.
- **Never silent.** A receipt that cannot be settled this way (a state the records do not explain, or one that cannot be written) puts the milestone under **Needs you** in plain words, with a one-click **Close the interrupted call**: the one more try counts as used, nothing is sent, and the build goes on. RUNESMITH.md gets one line when the milestone starts to wait, and one when you close the call. Nothing is shown while a one more try is actually running.
- Tests: `tests/test_interrupted_escalation.py` (the sequence from the run: a call cut short with no saved request, with a saved job that can be fetched, with one that failed, with one that was never sent, and with a packet that predates the link; the restart; Needs you and its one click; a settled receipt never rewritten), and the changed case in `tests/test_author_allowance.py`; the Needs you card's new choice in `tests/test_needs_you_view.mjs`.
**Runesmith keeps a map of itself and a scored plan for improving itself, and you set how much of its time that gets (2026-10-05).** Until now self-improvement was an automatic share of attention that only the repair organ could use. Now it is yours, it has a plan, and it goes first to what is hurting the work in front of it.
- **Self-improvement share.** Settings, Self-improvement: 10 to 90 percent in steps of ten, 20 by default, with its plain sentence ("2 of every 10 work turns go to improving Runesmith itself"). Of each block of 10 work turns that many are self-improvement turns, spread evenly (at 20 percent the 5th and the 10th); a counter in the home (`SELF_TURNS.json`) keeps it exact across restarts. A work turn is one repair opportunity or one scheduled step of the build work. This replaces the automatic attention share as the baseline in the Studio; the attention module is kept for its health signals (the Operations page says so), and a repair failure that keeps recurring counts as a struggle. The command line and the demos keep attention's own shares. Off means no self-improvement turns.
- **An active self map.** The map (`SELF_MAP.json`) is refreshed every round and after every scheduled step, with no model asked, and is no longer rewritten when nothing changed. It has a new `struggles` section: each milestone that is stuck or fails again and again, with what keeps failing (drafts of a large file fail their checks, no author allowance left, a split refused, answers cut off, checks that time out, a late answer ...), how many times and since when, and whether it is still struggling. It is derived from cheap records only: the worker's job history, the stuck policy's notes, the plan, the attention module, and the few drafts a job names.
- **A scored plan.** `SELF_PLAN.json` lists the improvement options Runesmith sees, from its map (struggles through a declared catalogue, for example large-file draft failures lead to "Targeted edits for large files" and module errors to "Author guidance for ES modules"), from Kaizen's ranked targets for the repair organ, and from affordances an organ leaves unused. Each has a score and a reason in plain words. The rule is fixed and declared (on the page and in `runesmith/app/self_plan.py`): benefit from the counts (10 points per doubling of the failure count, at most 60; a repair-organ target scores its percent of lost repairs), recency against the newest record (0 to 20; the clock is never read), and 20 when a trial gate exists. The same records always give the same plan.
- **Struggle first.** At a self-improvement turn Runesmith takes the first item of the plan, unless a milestone is struggling now: then it takes the best-scored option linked to that struggle. An item that is already planned is passed over, so the plan moves on; when nothing can run, the turn goes back to the project's work at once and Runesmith never idles.
- **Nothing changes without its gate.** Where a trial exists (the repair organ, through a Kaizen campaign) the campaign runs as before, held-out replay and then an online trial on your work. Every other item is recorded as "planned: needs a gate", visible to you and ready to be shared, and Runesmith's code, organs and generations are left exactly as they were.
- **Visible.** The Self-improvement page opens with the plan: a summary of the map, your share and how many work turns away the next self-improvement turn is, the next item and why (with the struggle it is linked to), the top ten with their scores, the struggles, and the scoring rule. RUNESMITH.md gets one line when the plan's first item changes and one when a campaign starts. The attention share on the Operations page is now your share.
- Tests: `tests/test_self_plan.py` (the turns for every share, the setting, the counter across a restart, the struggles section, deterministic scoring, the struggle priority with the sequence of a stuck milestone, no change without a gate, the run loop at every turn, RUNESMITH.md, the page and its route) and `tests/test_self_plan_view.mjs` (the page's card).

**Four Kaizen faults, found by running self-improvement on a Python project with a missing or dead Improver (2026-10-05).**
- **No Improver model, no campaign, and the repairs go on.** With self-improvement on and no model for the Improver's role, every round after the first few attempts replayed the whole validation split and then died with "no instrument serves role 'kaizen'", so nothing was repaired and the next round did the same. Now a campaign does not start without an Improver (and replays nothing if asked to), the Overview says once, in plain words, that self-improvement is on but no Improver is set up, RUNESMITH.md gets one line, and the repairs are served as usual. The note comes again only after an Improver has been there and gone.
- **A dead Improver no longer holds a round for an hour.** A campaign asked the Improver with the router's default waits (15 to 180 seconds between eight tries, and up to six failed calls), at least 54 minutes in one round when its route refused at once, and far longer when it hung until its time limit (up to 48 tries of that limit). A campaign now waits 5, 15 and 30 seconds between four tries and gives the campaign up after one failed call (the next one waits for new attempts): about a minute for a route that refuses at once, and four times its time limit for one that hangs, once. Any other failure inside a campaign ends the campaign, not the round. A campaign that got no answer at all is recorded as "improver unreachable", not as "nothing to improve".
- **"New attempts between campaigns" holds from one round to the next.** The count started again at every round, so the setting did nothing between rounds; it is now kept in the home (`KAIZEN_STATE.json`).
- **A model's own reasoning effort is respected.** A campaign asked for high effort in every call, overriding a model the owner had set to low (a model that spends its whole answer on hidden reasoning). It now asks for high only where the model has no setting of its own; every other call keeps its order.
- Tests: `tests/test_kaizen_bugs.py`.

**A stuck milestone is never left silent (2026-10-04).** In a long unattended run, a milestone's three tries failed, its one more try (another model) drafted files whose checks failed, and from then on every scheduled build ended at once with "No unambiguous ordinary author allowance for this lineage". The setting that breaks a stuck milestone into smaller steps was refused, so the project stood still for hours: nothing was built, nothing was shown to the owner.
- **Cause.** The guard that stops feedback from creating new tries looked for an ordinary try behind the newest failed draft. A draft made by the one more try (or by a requirement-clarification supplement) has none, since those are paid from their own single allowance, so the guard refused every build before it reached the "tries used up" verdict that the stuck setting and the page act on.
- **Fix.** The used-up verdict now comes before that guard, and a draft of the one more try or of a supplement no longer blocks the next ordinary try: with tries left, the build goes on from it as from any failed draft, and the new draft's lineage stops at it; with the tries used up, the milestone is stuck in the plain way, and the stuck setting acts. Revising such a draft by hand is still refused, now in words that say what to do (ask for smaller steps, edit the milestone, or set it aside).
- **Smaller steps no longer refused for a mislabel.** A proposed step that a model labelled a repair but that names a file its milestone has yet to create is recorded as a build, with a note on the proposal, instead of refusing the whole answer. A repair that names only files that exist now stays a repair. (The refusal had also spent the one break-down the setting makes.)
- **Needs you.** When the setting has nothing left to try for a stuck milestone (the default "wait for me"; the one more try used up or unable to change a file no model is shown; a break-down that was refused, turned down, waits for review, or has no room), the Overview shows a "Needs you" card: what is stuck, why nothing more happens by itself (a refused break-down says why) and the choices: try once more or ask for smaller steps, review the proposed steps, show the file to the models, edit the milestone (new wording, fresh tries), or set it aside. None of them grants tries. RUNESMITH.md gets one line when a milestone starts to wait, not one per step, and the card goes away when the milestone is edited, finished or set aside. Other ready milestones keep building meanwhile, as before.
- Tests: `tests/test_silent_stall.py` (the whole sequence through the worker, the supplement case, the split cases, the notice's life), and the changed repair-step test in `tests/test_breakdowns.py`.
**A file a step must change is never too large to show (2026-10-04).** A build that had to change a 40,179-byte program was refused: the program was over the 40,000 bytes a model could be shown whole, the refusal said "split it first", and splitting means changing a file no model is shown. The limits were set for small models; the models Runesmith is used with have large windows, and a model with a small one is already turned away before the call.
- **Shown whole up to 160,000 bytes.** A file the step must change (one you prioritized under Author context, one the step's words or its failing checks name, or one an earlier refused answer asked for) is shown whole up to 160,000 bytes (it was 40,000). The source a model is shown in all is up to 200,000 characters (it was 48,000), so such a file fits beside a little context. A file that is only context keeps its caps: 20,000 bytes, and up to 40,000 when the budget has room, and a larger one is shown in parts as before. The drafts a model may write stay at 400,000 bytes a file, so a file Runesmith builds is shown whole, or in parts, to the next step.
- **A model with a small window is skipped, not sent too much.** A model that takes few tokens at once (Groq's free tier, 8,000 a minute; an Ollama model's window) is still turned away before anything is sent when the request is too large, and the role's next model is asked. This now matters more, since a request can be larger; a model without a stated limit is sent the request as it is, so set one under Thinking power if its window is small.
- **"Split it first" only where it is true.** A file is refused as too large only when a draft could not hold it (over 400,000 bytes) or it is over 160,000 bytes with no line short enough to quote, so not even a part of it can be shown. The refusal and the summary of used-up tries now say that no model can split such a file and that you do it, by moving a part into a new file or breaking up long lines; they no longer say it for a file that is not UTF-8 text or that did not fit the budget, which get their own remedy, and the request for smaller steps no longer tells the model that a step can split such a file. A late answer is judged by the same sizes as a new call. The Studio's Author context drawer states the three sizes.
- Tests: `tests/test_file_cap.py` (a 40,179-byte program shown whole, with and without being prioritized; a context-only file keeping its caps; a late answer judged by what its call was shown; a request too large for the first model asked of the second, with no call to the first), and the existing tests of files shown in parts, now run at the old limits (`old_caps` in `tests/conftest.py`).

**A newcomer never meets a stale model name (2026-10-04).** A first run with a free Google AI Studio key failed at the first call: the "Google Gemini" tile suggested `gemini-2.5-flash`, and Google answered that this model "is no longer available to new users" and named its replacement. Model names go stale every few months for every provider, so the fix is general.
- **The provider's own list decides.** When a hosted tile has a key (pasted, or on **List models**), Runesmith asks the provider what it serves today and fills the Model ID with a recommended model, with a few other good choices as one-click buttons. For Gemini that is the newest generally available flash model: not a "pro", a "-lite" only when nothing else fits, a preview only when no stable one exists, and never an image, audio, live or embedding model. Other providers get the first suggestion their list contains, or the newest model of a known family. A model the owner typed or picked is never replaced; if it is not in the provider's list, a note says so.
- **Never empty.** Before the key is in, the Model ID already holds the tile's first suggestion, marked "(checked when you add your key)". If the owner pastes a key and presses **Save and test** at once, the list is read first, and a name that was only a suggestion is replaced by what the provider serves, with a note saying so. A local server (Ollama, LM Studio, llama.cpp) that is running shows what it has loaded.
- **The provider's hint becomes a button.** When a test fails with "no longer available", "deprecated" or "not found" and the answer names a replacement ("... please update your code to use models/gemini-3.8-flash"), the model's row says "Google Gemini suggests gemini-3.8-flash:" with **Use gemini-3.8-flash**. One click changes only the model name (the key, address and roles stay, and it is refused if the model was changed in the meantime), then tests it. Nothing switches without the click. A plan, a set of acceptance checks or a build correction that is refused for the same reason says the same in words ("The service suggests ...: press Test on that model").
- **Fresh fallbacks.** The suggested names used when a list cannot be read are current as of 2026-10-04: Gemini `gemini-3.8-flash` and `gemini-3.6-flash` (the example configuration too), Anthropic `claude-opus-5-5` and `claude-sonnet-5-5`, DeepSeek `deepseek-flash` and `deepseek-v4-pro`, and Together now has suggestions (`openai/gpt-oss-120b`, `meta-llama/Llama-3.3-70B-Instruct-Turbo`) instead of an empty box. The README's Gemini steps follow.
- Tests: `tests/test_fresh_models.py` (the recommendation rule on Gemini, OpenAI-style, Anthropic, local and OpenRouter lists, the hint parser on Google's exact answer in each wrapping, the fallback when listing fails, the one-click switch) and browser loop B2.07.

- **RUNESMITH.md: Runesmith's own log of what it did in your folder, and its version shown like a model's (2026-10-04).** Every folder the Studio works in gets a `RUNESMITH.md` at its top. A short header says what Runesmith is and carries its mark (the stone block with the R rune carved through it, drawn in 24 by 12 characters from the real artwork) and `Runesmith <version>`. Below it, one plain line for each event, newest last: a milestone added, dropped or done (with how many checks passed), a build applied (the file names only, and which model wrote the code, by its display name), checks approved or withdrawn, and what you decided (approve, turn down, discard, undo, keep or set aside the waiting work after a restart, one more try).

Every line is scrubbed first: links, key shapes (`sk-…`, `AIza…`, `Bearer …`, `token=…`), long hex or opaque runs and the exact values of the keys the home keeps become `[removed]`. A line has no line break, so nothing in it can forge another entry.

A `RUNESMITH.md` that Runesmith did not write (no header marker) is left alone, and is still read as instructions as before; only the log Runesmith wrote is skipped by the instruction reader.

- **Sandbox hardening after a security review.** Generation sharing made the organ sandbox matter against deliberately hostile code. Each gap below was first shown by a failing test, then closed:

  - `gc` introspection (it could reach and widen the guard's own allow-list);
  - sub-interpreter imports (Python-level audit hooks do not apply inside them);
  - `ctypes` imports, crafted code objects, tracing and adding audit hooks, and `signal`;
  - stderr floods (capped at 16 MB) and endless protocol lines (the host now reads lines with a bound).

On POSIX, `setrlimit` caps the address space and the file size and forbids new processes. Tests show the job refuses a spawn (WinError 1816) and a 600 MB allocation under a 200 MB cap, and that a sandboxed organ cannot hoard memory. These limits hold even for code that bypasses the hook.
- **`ledger` fix: one chain, however many writers.** `append` used to chain onto the tail each `Ledger` object cached. Two objects on one file wrote duplicate sequence numbers and broken links, and the steward and the Kaizen demo each held such a second object. - `opportunity`: `recall` is now always granted and returns an empty list when the host has no memory, as in experiments and smoke tests. Before, the contract promised an affordance that some hosts refused, and an organ that followed the contract crashed there.
- All text files use LF line endings, and a test keeps it that way. Digests are over bytes, and the project is cross-platform.
- The contract now says how to read a trace. Import-time module lines are included, and lines inside function bodies show which functions the failing tests called. A kernel test pins the trace end to end: the defect's line is traced, an uncalled function body is not, and a never-imported module is absent.

- `proposals`: `runesmith proposals [--write DIR]` turns judge-accepted fixes into unified-diff patches for human review. They are relative to the source as it was when the opportunity was served, and `git apply` refuses stale ones.
- `report` gains a **By model** table: calls, unusable-answer share, opportunities, strict repairs and output tokens per call for each model that answered. It is Runesmith's measured knowledge of its own instruments, and it carries across model changes. Call records now also name the answering instrument.
- **First Linux run** (Python 3.12.14 in a local container, no network, 1 CPU). The first full run gave 83 passed, 1 failed and 4 skipped. The skips are the three Windows-only Job Object and Windows API tests, plus the proposals test, because the image has no git.
  - The failure showed a platform difference, not a hole. On POSIX, `RLIMIT_FSIZE` equals the stderr cap, so a flooding organ's write fails with EFBIG exactly at the cap, and the organ dies before the host's poll saw the file grow *over* the cap. The flood was refused either way, but the verdict differed by OS (`OSError` vs `OutputFlood`).
  - `sandbox` now checks *at* the cap and classifies an organ that dies at the cap as `OutputFlood`, so the verdict is the same everywhere.
  - The kernel, OS-limit and proposal tests then passed on Linux (26 passed, 4 skipped) and on Windows (25 passed).
  - A second full Linux run passed: 84 passed, 4 skipped.
- **Fix: organ and replay sources are written as exact bytes.** On Windows, text-mode writes turned every LF into CRLF.
  - Affected: the Kaizen candidate organ (`improve.py`) and replayed task sources (`ExperienceStore.materialize`).
  - Effect: an organ frozen on Windows differed in bytes from its author's text, so it carried two digests. Behaviour was identical, because Python reads source with universal newlines.
  - Found by the new byte-level end-to-end test of the manual author. SR5's B is one such organ: file bytes `efef2b5c…`, author text `38d4be00…`. This is recorded in the SR5 and SR6 protocols.
  - A regression test pins `materialize`.
  - A flaky assertion in the loop test is fixed too: it did not allow the freeze rule's `within_noise` decision, which a timing tie can produce.
- `manual`: **a chat model as the author, relayed by hand.** Anyone with access to a strong model only through a chat window can author generations: a campaign needs at most a few author calls, and the result runs on free models.
  - An instrument of kind `manual` writes each request as a paste-ready file under `<home>/manual/` and waits for the reply.
  - `runesmith manual list / show / answer [--clipboard | --file] [--model]` hands the reply back. Replies are checked against the request's schema first, so a person can ask the model to fix its answer before it counts.
  - Replies may be written the way chat models write: prose around a ```` ```json ```` block, raw line breaks inside strings, and whole source files in named `@block:NAME` fenced blocks, which need no escaping. CRLF and UTF-16 are handled.
  - A request nobody answers is a transport failure, so the work is censored, never scored. Router retries wait on the same content-addressed request.
  - Receipts keep `answered_by` next to the instrument's label, and the Kaizen attempt record prefers it.
  - `demo --kaizen --manual-author` puts your chat model's change through the demo's qualification and trial. An end-to-end test relays SR5's author answer as a chat reply with CRLF endings and a named block, and asserts that the activated organ is byte-identical to it.
  - Guide: [docs/CHAT_AUTHOR.md](docs/CHAT_AUTHOR.md).
- **Safety:** `discover` and `envmap --probe` run an object's tests on a throwaway copy, with no bytecode writes, so Runesmith never writes into the objects it inspects. A test checks the repository byte for byte. `in_place=True` remains available to library callers.
- `attention`: **SPC drift detection**. A Bernoulli CUSUM watches strict-success yield against Runesmith's own baseline: the Wilson lower bound of its first 30 outcomes. It moves attention to blocked when yield drifts down although no single failure recurs, for example after a model or environment change. Its operating characteristics were simulated and are reproducible with `docs/simulations/drift_cusum.py`:
  - at most 3.7% false alarms within 200 stable opportunities;
  - a drop from 0.6 to 0.15 detected with a median delay of 22.
  The baseline resets when a new generation is activated.
- `attention` state now persists in `<home>/ATTENTION.json`, so struggle and drift are tracked across `run` invocations and steward rounds. Before, each run started fresh.
- `report` shows attention: its mode, the resulting Kaizen share, the blocking signal, the last change with its reason, and the drift chart's state. It shows why Runesmith is spending more or less time on itself.
- `discover`: **triage**. A failing test that only an environment change can fix (a missing third-party module, or a network dependency) is marked `environment`. The run loop and the steward skip it: no model call is spent, and it is recorded in the ledger. The rule is conservative. A missing module that exists in the object's own `src/` stays a repairable source defect, and anything unrecognised is left to the repair attempt. Discovery runs pytest with a wide terminal, so summary reasons are never truncated.
- `envmap`: a **document-collection template**. It reads only and executes nothing. It measures internal Markdown link integrity in bands, and it knows:
  - inline and reference links;
  - anchors and URL-encoding;
  - `file:line` code references;
  - that code fences are ignored.
  It also records a ladder (documents → index → links resolve) and the first broken links as examples. External links are not checked, and that is listed as an unknown. First real use: MillinerOS `docs/` has 78 documents and 499 internal links, none broken (band *optimal*), and its next rung is an index.
- `doctor`: `runesmith doctor [--offline]` checks Python, pytest, the home, the ledger chain, the active generation (its organ files and kernel), the instruments (key present, endpoint reachable) and disk space. It gives a fix for each problem and never prints a secret.
- `generations requalify`: after a Runesmith update, it re-freezes the active organs under the new kernel after a static check and a confined smoke test. The organs are byte-identical; the ledger records the requalification and the compare-and-swap activation.
- `share`: `generations export <id> --to FILE` and `generations import --from FILE`, so improvements compound across people. An import must pass these checks, in order:
  - archive members restricted to a manifest and `organs/**.py`, with no traversal and bounded sizes;
  - digest match;
  - static check;
  - a confined smoke test.
  It is then frozen inactive, bound to the receiver's kernel with provenance naming the source, and an online trial is opened. It is activated only by winning that trial. There is also a new `trial --open <id>`.
- `steward`: `runesmith steward WORKSPACE [--rounds N --interval S --exclude NAME]` is the top-level "lowered into an environment" mode. Each round maps the workspace, discovers failing tests across all Python objects on throwaway copies, and serves only new work. Opportunity identity includes a digest of the object's `src`, so unchanged work is never re-served. The seed stays fixed across rounds, so the Kaizen validation split never leaks. The steward interleaves Kaizen and trials, writes the report and proposals, never edits an object, and never probes excluded objects.
  Objects without a `src/` layout are skipped with a stated reason, because the shipped repair organ needs `src/`. Before this fix, one flat-layout repository crashed the round.
